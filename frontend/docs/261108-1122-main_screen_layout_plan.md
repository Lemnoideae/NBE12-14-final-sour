### 2-2. 긴 학교명 왕복 표시 (3단계, S2)

- `src/components/MarqueeText.tsx` (신규): 칸 폭과 글자 폭을 재고(`ResizeObserver`로 웹폰트 로딩·폭 변화 반영), **넘칠 때만** `data-overflowing="true"`, 이동 거리·시간 CSS 변수, 전체 이름 `title`을 설정한다.
  - 양 끝 페이드: `mask-image` 선형 그라데이션 10px(`MARQUEE_FADE_PX`). 트랙에 같은 폭의 여백을 둬 왕복 시작·끝에서 첫·끝 글자가 페이드에 가려지지 않는다.
  - 속도: 18px/s(`MARQUEE_SPEED_PX_PER_S`), 양 끝에서 주기의 30%씩 멈춤, 한 방향 최소 5초(`MARQUEE_MIN_DURATION_S`). 조금만 넘쳐도 끝에서 약 1.5초 머문다.
  - `prefers-reduced-motion: reduce`: 애니메이션·페이드를 끄고 말줄임(`…`)으로 표시하며 `title`로 전체 이름을 제공한다.
- `src/index.css`: `.marquee-*` 규칙과 `@keyframes marquee-pingpong`(alternate 왕복) 추가.
- `src/components/TopHUD.tsx`: `schoolName` prop(기본 `한양대학교`)을 `MarqueeText`로 표시. 로고 대체 글자도 학교명 첫 글자에서 파생.
- `src/App.tsx`: **[시연] 학교명** 선택(기본 `한양대학교` / 9자 `서울과학기술대학교` / 긴 이름 `한국방송통신대학교 프라임칼리지 서울캠퍼스`). 목업 표시 확인용 값이며 실제 학교 데이터가 아니다.

브라우저 확인 (390px 프레임, 학교명 칸 159–163px): 9자 이름은 들어가 정지, 긴 이름(240px)은 97px 왕복(한 방향 7.7초).

### 2-4. S3·S4 연합·대결 알림 배지와 내비 통일

- 배지 조건(`src/App.tsx`, 에이전트 정의): **받은 연합 신청 대기** 또는 **우리 연합이 받은 대결 신청 대기** 또는 **우리 연합 대결 예정·진행 중**. 우리가 보낸 신청의 응답 대기는 알림으로 보지 않는다. 초기 목업 상태에서는 꺼져 있다.
- Context로 제공하므로 순위·상점·방문·지도·채팅·방명록 등 `BottomNav`를 쓰는 모든 폰 화면이 같은 5칸이 된다(별도 prop 전달 없음). 가장 좁은 2대 폰 지도 비교(내비 폭 333px)에서도 라벨이 넘치지 않음을 확인했다.
- 트레이드오프: 내비 동작이 Context에 의존하는 암묵적 의존이 생긴다. 대신 화면 10곳·핸들러 9곳에 prop을 늘리지 않는다.

### 2-7. D2 캠퍼스 탭 넘침 해소

- `src/components/CampusView.tsx`: 캠퍼스 클릭 영역 `h-[375px] sm:h-[400px]` → `h-[375px]`. `sm:`은 **창 폭**(640px 이상) 기준이라 데스크톱에서 보는 폰 프레임 안에서만 400px이 되었고 실제 휴대폰에서는 375px이었다. 카메라 기준 비율 `CAMPUS_DEFAULT_ASPECT = 367/358`(`src/data/campusGeometry.ts:12`)도 375px 칸(테두리 제외 358×367) 기준이므로, 목업 표시가 설계 비율과 같아진다. 장면은 칸 비율을 재서 `slice`로 맞추므로 구도 계산 변경은 없다.
- `src/components/DialogPanel.tsx`: `compact`(메인·채팅1·방명록1 화면에서 사용)일 때 기여도 상자를 클리커 상자에 합쳐 한 상자로 표시. 표시 문구는 모두 유지하고 기여도 설명(`내 누적 기여 점수 · 구매/강화 시 차감`)만 `title`로 이동. 버프 상태는 "다음 Lv" 줄 오른쪽으로 이동. `compact={false}`는 기존 두 상자 배치 유지.
- 가장 긴 조합(`다음 Lv.10 · 클릭당 1,000점` + `커피 한 잔 · 30초 남음 · 다음 클릭 1회`)을 브라우저에서 주입해도 해당 줄 높이 15px 유지, main 넘침 없음(실측).
- 채팅 비교 화면(`ChatScreen1Phone`)은 자체 `justify-between` 배치라 패널과 채팅 바 사이 빈 공간이 생긴다(넘침 아님, 확인).

## 3. 목업 한정 사항

- 연합·대결 화면들(`*ScreenPhone`)은 자체 프레임과 뒤로가기를 쓰며 하단 내비가 없어 연합·대결 버튼의 "활성" 상태는 표시되지 않는다.
- 배지는 로컬 목업 상태 기준이다. 실서비스에서는 서버 이벤트(신청 수신·경기 시작)로 갱신해야 한다.
- `[시연] 학교명`과 폰 프레임(390×845), 상태 표시줄·홈 바는 시연용이다.
