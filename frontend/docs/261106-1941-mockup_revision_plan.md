# 팀장 의견 기반 목업 수정안

Last updated: 2026-11-08 19:22 +0900

## 범위와 기준

- 목적은 **팀장 의견을 화면·상태·시연 흐름에 반영하는 것**이다. 백엔드·DB·API 구현은 이번 범위에서 제외한다.
- 기존 UI와 비교 화면은 재사용하며, 채팅·방명록 등 이미 만든 선택 기능은 유지한다.
- 이전 문서 `261106-1903-next_steps.md`(Issue [#13](https://github.com/Lemnoideae/261106-mkup/issues/13)로 이동)보다 이번 문서의 목업 범위와 팀장 의견을 우선한다. 별도 소비 재화 도입은 전제로 삼지 않는다.
- **팀장 의견**은 전달받은 방향, **권고**는 목업 적용 제안, **미확정**은 추가 결정이 필요한 사항이다. 팀장 의견에 포함된 데이터 구조도 최종 확정된 DB 설계로 취급하지 않는다.

## 1. 반영할 기본 방향 — 팀장 의견

| 항목 | 방향 |
|---|---|
| 기여도 | 사용자의 기여도를 아이템 구매와 클리커 강화에 사용한다. 별도 클리커 EXP는 두지 않는다. |
| 클리커 | 단계별 세기를 공통 데이터로 두고, 기여도를 차감해 사용자의 현재 클리커를 다음 단계로 변경한다. |
| 버프 | 중첩하지 않는다. 이미 사용 중인 버프를 재사용하면 기존 효과를 교체하며, 정해진 지속시간 후 만료된다. |
| 학교 성장 | 학교 기여도가 단계별 기준 수치에 도달하면 성장한다. |
| 순위 범위 | 전국 학교별, 교내 학과별, 교내 개인별 순위를 제공한다. |
| 동점 정렬 | 학교는 학교명 오름차순, 개인은 닉네임 오름차순으로 정렬한다. |

## 2. 목업 변경 목록

| 영역 | 수정할 내용 |
|---|---|
| 공통 상태 | 별도 `clickerExp`·`clickerMaxExp` 및 EXP 증가·구매 처리를 제거한다. 메인과 상점이 같은 기여도·클리커 상태를 사용한다. |
| 클리커 데이터 | 단계별 레벨·세기·강화 비용을 정적 목록으로 관리한다. 현재 클리커 ID로 레벨·세기를 조회하는 방식을 권고한다. 레벨과 ID를 독립 상태로 중복 관리하지 않는다. |
| 메인 정보 패널 | EXP·숙련도 표시를 보유 기여도·다음 강화 비용 안내로 변경한다. 세기는 `클릭당 20점`처럼 실제 값으로 표시한다. |
| 상점·강화 | 기여도 차감 후 클리커를 변경한다. 비용·잔여 기여도·현재/다음 세기를 표시하고, 잔액 부족·최고 단계 상태를 제공한다. |
| 레벨 하락 안내 | 구매 후 잔액 감소만으로 레벨을 내리는 기존 처리와 경고 문구를 제거하는 것을 권고한다. 이는 구매로 현재 클리커가 바뀌지 않는다는 해석에 따른다. |
| 아이템 | 별도 강화 재료의 필요성을 재검토한다. 버프형 아이템은 실제 클릭 효과와 연결하고 효과·남은 시간을 표시한다. |
| 학교 성장 | 학교 점수에 따라 레벨·캠퍼스 이미지·성장 안내·잠금 상태를 함께 갱신한다. 기존 단계 이미지를 재사용한다. |
| 순위 | 교내 학과·개인 목록을 내 학교 소속 데이터로 구성한다. 점수 내림차순과 동점 보조 정렬을 적용하고, 탭 이름에 집계 범위를 명시한다. |
| 비교 화면 | 채팅·방명록 비교 화면 등에도 변경된 기여도·클리커 표시를 동일하게 반영한다. |

진행 막대를 유지한다면 별도 EXP가 아닌 **다음 강화 비용 대비 보유 기여도**를 표현한다. 버프 지속시간의 ‘5분’은 예시이며 모든 아이템의 고정 지속시간으로 취급하지 않는다.

## 3. 추가 확인 결과와 남은 미확정 사항

정책 출처는 사용자가 추가로 전달한 팀장 확인 및 권고안 진행 승인이다. 아래는 최종 서버/DB 계약이 아니라 이번 목업의 적용 기준이다.

| 항목 | 이번 적용 기준·확정 수준 |
|---|---|
| 소비 후 개인 순위 | **팀장 확인:** 1,000점에서 300점을 쓰면 700점으로 집계한다. 별도의 소비 불가 획득 누계를 만들지 않는다. |
| 소비 대상 | **팀장 확인:** 구매·강화는 `User.누적 기여 점수`에서만 차감한다. 학교·학과 점수는 줄이지 않는 권고를 적용한다. |
| 화면 용어 | `내 누적 기여 점수 · 구매/강화 시 차감`으로 원래 필드의 의미를 밝히고, 현재 값은 `보유 기여도`로 표시한다. |
| 클리커 유지 | **권고 적용:** 일반 구매로 현재 클리커를 변경하거나 잔액 감소 때문에 레벨을 내리지 않는다. |
| 버프 범위 | **권고 적용:** 종류와 무관하게 1개만 활성화한다. 재사용/다른 버프 사용 시 효과를 교체하고 지속시간을 다시 시작한다. |
| 비용·성장 기준 | **목업 임시 값:** `src/data/gameRules.ts`의 공통 목록을 사용한다. 실제 밸런스는 미확정이다. |
| 동점 순위 | 학교명·닉네임 오름차순을 적용한다. 학과명 오름차순, 동일 이름일 때 ID 정렬, 연속 순위 번호는 **목업 임시 규칙**이며 공동 순위 정책의 최종 확정은 아니다. |
| 피버·치명타·자동 획득·재료 | 최종 채택은 **미확정**이다. 기존 피버/치명타 연출은 유지하고 추가 피버 보너스는 만들지 않는다. 자동 획득 도우미·별도 강화 재료·깃펜은 삭제하지 않고 정책 검토 중인 기존 시안으로 남기며 구매는 막는다. |

버프 계산은 목업에서 `반올림((기본 세기 × 치명타 배수) × 버프 배율 + 버프 가산점)`을 사용한다. 기존 치명타 확률 25%, 치명타 2배를 유지하며, 커피 30초·깃발 60초·열람권 5분 내 다음 클릭 1회는 임시 시연 수치이다. 깃발의 효과도 실제 전체 학교 사용자 적용이 아닌 **내 클릭 +5%의 목업 효과**로 명시했다.

## 4. 적용 순서

1. 소비가 개인·학교·학과 순위에 미치는 영향과 버프 교체 범위를 확정한다.
2. 클리커 단계·강화 비용·아이템·학교 성장 기준의 공통 목업 데이터를 작성한다.
3. 메인·상점 상태를 통합하고 EXP 및 레벨 하락 관련 표시를 정리한다.
4. 강화·버프 결과를 클릭 점수에 연결한다. 버프 재사용 시 지속시간을 새로 시작하고 이전 타이머가 새 효과를 종료하지 않도록 한다.
5. 학교 성장과 순위 데이터·정렬을 연결하고 비교 화면에도 반영한다.

## 5. 시연·회귀 검증 체크리스트

체크는 `tests/gameModel.test.ts`와 `tests/gameUi.test.ts`의 **계산 규칙 및 DOM 통합 테스트** 통과를 뜻한다. 실제 브라우저 레이아웃·이미지 크롭 외관·실기기 터치는 포함하지 않는다.

- [x] 클릭으로 기여도가 증가하고, 별도 클리커 EXP는 증가하지 않는다.
- [x] 강화 시 기여도가 정확히 차감되고 현재 클리커·세기가 바뀐다.
- [x] 구매·강화 결과가 화면 이동 후에도 유지된다.
- [x] 잔액 부족·최고 단계에서는 강화가 진행되지 않는다.
- [x] 일반 구매로 클리커 레벨이 내려가지 않는다.
- [x] 버프 재사용 시 효과가 중첩되지 않고 지속시간이 다시 시작된다.
- [x] 이전 버프의 만료 시점이 새 버프를 조기에 종료하지 않는다.
- [x] 버프 만료 후 기본 세기로 복귀한다.
- [x] 성장 기준 경계값을 검증하고, 시연 선택 시 이미지 참조·HUD 레벨·미해금 안내가 같은 단계로 바뀐다.
- [x] 학과·개인 순위에는 내 학교 소속 데이터만 표시된다.
- [x] 동점 샘플이 정해진 이름 순서와 순위 번호 규칙에 맞게 표시된다.

- [x] touchstart 다음 click 입력이 이어져도 점수를 두 번 주지 않는다 — DOM 이벤트 시퀀스 기준.

## 6. 구현 결과와 검증 한계

- 공통 수치: `src/data/gameRules.ts`; 점수·강화·버프 규칙: `src/utils/gameModel.ts`; 공유 컨트롤러: `src/hooks/useMockGame.tsx`; 정렬·교내 샘플: `src/data/mockRankings.ts`.
- 메인 상점은 독립 상점 컴포넌트를 재사용한다. 캠퍼스 이미지는 기존 성장 시트에서 현재 단계 영역을 선택한다. 화면 이동으로 상태가 초기화되지 않지만, 브라우저 새로고침 후 저장/복원은 이번 범위가 아니다.
- 성장 시트의 명시적인 시연 버튼은 학교 점수를 선택 단계의 기준값으로 설정한다. 개인·학과 점수와 클리커·버프는 건드리지 않는다.
- **확인:** `npm run test` 24개 통과, `npm run lint` 통과, `npm run build` 통과. 테스트 실행 환경은 Node `v26.10.0`이다.
- **확인 및 제한:** 변경 TS/TSX 24개 경로에 활성 LSP 검사를 실행했고 마지막 검사에서 진단은 0개였다. 다만 재검사 6개 경로는 서버의 무응답/정상 결과 통지 제한 때문에 clean 여부가 미확정으로 반환되었다. 전체 TypeScript 컴파일 검사는 별도로 통과했다.
- **기존 경고:** 빌드 시 `vite.config.ts:11`의 `__dirname`에 대해 향후 native config loader 호환 경고가 나온다. 이번 목업 범위 밖이므로 설정을 바꾸거나 경고를 숨기지 않았다.
- **미검증:** Chromium 실행이 프로젝트 샌드박스의 소켓 생성 차단 및 홈 설정 경로 쓰기 제한으로 중단되었다. 실제 브라우저/모바일의 레이아웃, 스크롤, 이미지 외관, 터치 제스처 검증은 완료하지 않았다. 제한 우회 재시도는 하지 않았다.
