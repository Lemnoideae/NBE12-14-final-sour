1. 서비스 개요

1-1. 서비스명 - 대대대

서비스명: 대대대
작명 이유: 대학교 대 대학교의 줄임말, 클릭 연타 느낌의 대대대

1-2. 한 줄 소개 (30자 이내)

본인 학교를 키워 옆 학교랑 싸우기

1-3. 엘리베이터 피치 (3~5문장)

"대대대"는 학교 이메일로 소속을 인증한 대학생이, 클릭 횟수를 통해 자신의 학교 점수를 쌓고, 다른 학교와 순위를 겨루는 대학 대항 클릭 게임입니다. 사용자는 공강이나 쉬는 시간에 짧게 참여 가능하고, 자신의 기여가 학교 점수와 순위에 반영되는 과정을 확인할 수 있습니다. 클라이언트가 일정 주기마다 클릭 수를 모아 보내면, 서버가 유효성을 검증한 뒤 점수에 반영합니다. 학교 구성원의 가벼운 협동과 학교 간의 경쟁을 연결하되, 부정한 점수 누적을 줄여 신뢰할 수 있는 경쟁 경험을 제공하는 것이 목표입니다.

2. 문제 정의 (Why)

2-1. 어떤 문제를 해결하려는 것인가?

대학생들의 학업 스트레스와 진로에 대한 부담으로 정신건강 문제가 악화됩니다.

이러한 스트레스를 해소하기 위한 방법으로 대표적인 방법으로는 영화 감상을 포함한 취미 생활, 음주, 운동, 친구와의 상담, 온라인 게임입니다.
(관련 기사 - 대학생들 ‘행복지수’보다 ‘스트레스지수’ 더 높다…스트레스 원인 1위 ‘취업’)

저희는 스트레스라는 문제를 해결하기 위해 게임이라는 방안을 정했습니다.

4-2. MVP 기능 구현 후 추가 구현 기능

1. 연합 기능
	- 원하는 대학이랑 연합하여 다른 연합 대학이랑 일정 기간(최소 6시간~최대 n일) 동안 대결할 수 있는 기능
	- 연합 (2:2), (3:3) 대결 보상 -> 승리 시 패배 팀의 점수를 나눠 가지는 형태
2. 경쟁 학교 이스터에그
	- 고려대 vs 연세대와 같은 경쟁 학교끼리 대결할 수 있는 기능
	- 공격 점수 * 1.1배
3. 채팅 기능
	- 대학 내 채팅 + 연합 내 채팅 + 채팅 메시지 필터링
4. 방명록 기능
	- 타 학교 방명록 기능(닉네임 + 학교이름 표시)
5. 메일 기능
	- 고객문의 메일 송신 기능
6. 광고 기능
7. 수익 모델 기능
	- 사용자가 본인 학교 커스텀 로고
	- 결제 정합성, 결제 동시성(제일 마지막에 로고를 바꾼 사람걸로)
8. 이상 탐지
	- 데이터를 분석하여 사람이 발생시킨 트래픽인지, 매크로나 불법 프로그램을 이용한 트래픽인지 탐지
9. 특정 장소 이스터에그
	- 도서관에서 클릭 시 추가 점수
10. 타 학교를 부수는 기능 -> 경험치를 올리는 속도보다는 느려야 함

4-3. 사용자 시나리오 (1~2개)

시나리오 1 — 처음 참여해 학교 점수 올리기
1. 사용자가 접속해 자신의 학교 이메일을 입력해 코드를 요청한다.
2. 학교 이메일로 받은 코드를 제출한다.
3. 인증 후 서버가 확정한 소속 학교로 게임에 참여한다.
4. 클라이언트는 학교를 클릭 한다.
5. 사용자는 서버가 확정한 내 기여와 학교 순위를 확인한다.
시나리오 2 — 타 학교 방문
1. 사용자는 탑뷰를 통해 참여 학교들을 확인한다.
2. 원하는 학교를 클릭하여 학교를 구경한다.
3. 타 학교에 방명록을 남긴다.

6-2 기능 흐름

1. 대학교 이메일 검증 및 회원가입

1. 클라이언트는 대학교 이메일을 입력하고 코드 요청
2. 서버는 Redis에 TTL N분인 이메일 데이터를 하나 생성
3. 서버는 클라이언트가 입력한 이메일에 코드를 전송
4. 클라이언트는 코드 인증
5. 클라이언트는 회원 정보를 입력 후 회원 가입을 서버에 요청
6. 서버는 회원 정보 중 이메일이 (2번)Redis에 저장한 이메일과 일치한지 검사
7. 일치하면 회원 생성, 불일치하면 회원 가입 실패 응답

2. 클릭

1. 프론트는 1초 동안 사용자의 클릭 횟수를 수집
2. 1초마다 클릭 횟수를 서버에 보냄
3. 서버는 비정상적인 트래픽인지 검증하고 Redis에 저장
4. Redis에서는 각 학교 점수, 학과 점수, 학생의 기여도를 저장함
5. Redis는 학교 점수와 학생의 기여도, 학교 로고를 응답함
6. 서버는 학교 점수와 학생의 기여도, 학교 로고, 다른 사람의 학교 클릭 횟수를 프론트에 응답함

3. 기여도 데이터 저장

서버는 1분마다 Redis에 저장된 학교 점수, 학과 점수, 학생의 기여도를 DB에 배치 업데이트로 저장함.

4. 채팅 (WebSocket)

1. 클라이언트는 대학교의 채팅방 채널을 구독
2. 서버는 Redis에서 위의 학교 채널을 구독
3. 클라이언트는 서버에 채팅 메시지를 보냄
4. 서버는 JWT로 소속 학교 확인 그리고 메시지 필터링
5. 메시지를 DB(DynamoDB)에 저장
6. 서버는 Redis의 해당 채널에 메시지를 보냄
7. Redis는 구독한 서버에 받은 메시지를 다시 전송
8. 모든 서버는 메시지를 구독한 클라이언트들에게 보냄
9. 프론트는 채팅을 최신화
