# M1 학교 식별·지도 데이터 통합 계획

Last updated: 2026-11-08 20:20 +0900

## 1. 결론

학교 데이터를 하나의 조회 모듈로 모으고, 전국·충청 지도가 이 모듈만 읽도록 바꾼다. 작업 순서는 M1-A(공통 데이터) → M1-B(지도 동작) → M1-C(로고·배치 점검)이다. 각 단계에 회귀 테스트를 함께 넣는다.

- **범위:** [Issue #16](https://github.com/Lemnoideae/261106-mkup/issues/16)의 항목 1~15(M1)만 다룬다. 지도 → 방문 → 복귀(M2, 항목 16~20)는 이 계획에 넣지 않는다. 다만 M2가 바로 이어지도록 지도의 권역·검색 상태를 상위 컴포넌트로 올려 두는 일(4-2절)은 포함한다.
- **필수 기능과의 관계:** 기획서 4-1 #6(타 학교 방문)과 #7(지도 탑뷰에서 상위권 학교 점수와 모든 학교 로고 출력)은 필수다. M1은 #7을 직접 다루므로 선택 기능이 아니다.
- **결정:** 5장의 D1~D3은 사용자 지시("그럼 일단 기본안으로 진행해줘.", 2026-11-08)로 기본안을 적용했다. D1에 따라 필수 기능 #7의 "모든 학교 로고 출력"은 **미충족**으로 남는다. → 이후 사용자 지시(2026-11-08 "로고는 임시 배지로 인정")로 목업 기준 충족 처리(8-1절).
- **구현 상태:** M1-A·M1-B 구현 완료, M1-C는 배치·점검은 완료했으나 로고 자산 0/76으로 미완료. 따라서 4-3 완료 기준에 따라 **M1 전체는 완료가 아니다.** 결과는 8장에 적었다. **이후 로고 판정이 해소돼(8-1절) 목업 기준 M1을 완료로 본다.**

## 4. 작업 계획

### 4-1. M1-A 공통 학교 데이터 (항목 1~5)

**목표:** 지도·순위·(이후) 방문이 같은 학교 ID로 같은 이름·점수·순위·성장 단계를 읽는다.

| 데이터 역할 | 위치 (권고) | 내용 |
|---|---|---|
| 기본 학교 정보 | `src/data/universitiesData.ts` (유지) | ID, 이름·약칭·첫 글자, 권역·필터 권역·도시, 배지 색, **초기 점수**. 고정 `rank`·`isTop3`·`isMySchool`과 지도 좌표는 이 파일에서 뺀다 |
| 지도 표현값 | `src/data/schoolMapLayout.ts` (신규) | 전국 좌표, 충청 권역 좌표·세부 지역·인출선, 군집 위치·스타일. 모두 학교 ID 또는 권역 키로 연결 |
| 게임 표시값 | `src/data/schoolDirectory.ts` (신규) | `getSchoolViews(schoolScore)`: 기본 정보 + 현재 점수 + 전국 순위 + 성장 단계(`getCampusStage`) + `isMySchool` + `isTop3`. `getSchoolById(id)`, `getTopSchools(n)`, `countByRegion()` |

- [x] **1. ID 통일:** 선택·조회·이동은 모두 `id`로 한다. 지도 컴포넌트가 `UniversityItem` 객체를 넘기던 곳(`onSelectSchool(school)`)은 ID를 넘기도록 바꾼다. 이름이나 배열 위치로 학교를 찾는 코드를 남기지 않는다.
- [x] **2. 역할 분리:** 위 표대로 나눈다. `OFFICIAL_SCHOOL_RANKINGS`(`src/data/rankingsData.ts`)는 사용처가 없으므로 지운다. 충청 지도의 학교 복사본은 4-2절에서 지운다.
- [x] **3. 공통 조회:** `getSchoolViews`는 기존 `getSchoolRankings()`의 정렬·동점 규칙(`rankEntries`)을 그대로 쓴다. 순위 계산을 두 곳에 만들지 않는다.
- [x] **4. 점수 출처:** 내 학교는 `useMockGame().state.schoolScore`, 다른 학교는 공통 목록의 초기 점수를 쓴다. 개인 기여도(`contribution`)는 학교 점수에 섞지 않는다. 컴포넌트는 `useSchoolViews()` 훅(신규, `useMockGame` 사용)으로 읽는다.
- [x] **5. 파생값:** `isMySchool`은 `MY_SCHOOL_ID` 비교, `isTop3`는 계산된 순위 ≤ 3, 군집 학교 수는 `countByRegion()`으로 구한다.

**완료 기준:** 같은 학교 ID의 이름·점수·순위·성장 단계가 지도 목록, 지도 TOP 3, 순위 화면에서 같다. 내 학교 점수가 성장 경계값이나 다른 학교 점수를 넘으면 세 화면이 함께 바뀐다.

### 4-2. M1-B 전국·권역 지도 동작 (항목 6~11)

- [x] **6. 고정 데이터 교체:** `Screen1NationalMap`의 `top3Schools`·군집 학교 수와 `Screen2RegionMap`의 `chungcheongSchools`를 지우고 `useSchoolViews()` + `schoolMapLayout`으로 그린다.
- [x] **7. 충청 배치 보존:** 충청 지도의 기존 좌표·세부 지역·인출선은 ID별 메타데이터로 옮긴다. 빠진 6개 학교의 좌표는 D3 결정에 따라 추가한다. 레이아웃이 공통 목록에 없는 ID를 참조하거나 중복되면 테스트가 실패하게 한다.
- [x] **8. 권역 기준:** 필터는 `전체 / 수도권 / 강원 / 충청 / 영남 / 호남 / 제주`이며 데이터의 `filterRegion`을 쓴다. 군집 키(`서울·인천·경기`, `충북·충남·대전`, `경상`, `전라`)에서 필터 권역으로 가는 대응표를 `schoolMapLayout`에 둔다. 지금처럼 `includes('충남')` 같은 문자열 비교로 처리하지 않는다.
- [x] **9. 권역 + 검색:** 선택한 권역 안에서 이름·약칭·도시·첫 글자로 검색한다. 결과 건수, 검색어 지우기, 0건 안내 문구를 표시한다.
- [x] **10. 선택 이벤트 통일:** 목록 행, 지도 마커, TOP 3 리본이 모두 같은 `onSelectSchool(id)`를 호출한다. 군집을 누르면 학교 선택이 아니라 해당 권역 필터·확대로 이동한다(D2). 군집 모달의 `충청 확대 지도 보기` 고정 버튼은 누른 권역으로 가도록 고친다.
- [x] **11. TOP 3 파생:** `getTopSchools(3)`으로 그린다. 순위가 바뀌면 리본의 학교·점수·순위가 함께 바뀐다.
- [x] **상태 위치 (M2 대비, 권고):** 권역·검색어·선택 학교 ID를 `MapScreenPhone`으로 올리고, 두 지도 컴포넌트는 props로 받는다. 지금은 전국↔충청 전환 때 검색어가 사라진다. M2에서 방문 후 지도 문맥을 복원하려면 이 상태가 지도 컴포넌트 밖에 있어야 한다.

**완료 기준:** 7개 권역 모두에서 필터와 검색이 동작한다. 같은 학교를 목록, 마커, TOP 3 중 어디서 눌러도 같은 ID가 전달된다. 군집 숫자, 목록 건수, TOP 3가 공통 데이터와 일치한다.

### 4-3. M1-C 로고·지도 배치 점검 (항목 12~15)

- [x] **12. 전체 점검을 테스트로:** 공통 목록의 모든 학교에 대해 ① 전국 좌표 또는 권역 확대 화면 좌표가 있는지, ② 로고 경로 또는 임시 배지 표시가 정해져 있는지 검사하는 테스트를 만든다. 학교 수는 데이터에서 센다. 화면 문구의 `76개`도 데이터에서 계산한다(`Screen1NationalMap.tsx:466`).
- [x] **13. 로고·이름 연결:** 마커·목록의 학교 버튼에 학교명이 들어간 접근 가능한 이름(`aria-label`)을 붙인다. 밀집 구간은 권역 확대(D2)로 개별 학교를 보고 고를 수 있게 한다.
- [x] **14. 임시 배지 구분:** 로고가 없는 학교는 첫 글자 배지를 쓰되, 임시 대체임을 데이터(`logoStatus: 'placeholder'`)로 표시한다. D1 승인 전에는 이것을 "로고 출력 요구 충족"으로 기록하지 않는다.
- [x] **15. 점검 결과 기록:** 학교 ID별 로고 상태와 배치 문제를 결과 보고서에 표로 남긴다. 현재 확인된 상태는 로고 0/76, 전국 좌표 누락 38/76, 충청 확대 지도 누락 6/24다. 해결한 뒤에는 누락 0건이라고 기록한다.

**완료 기준:** 모든 학교가 지도 위에서 보이고 선택할 수 있으며, 선택된 ID가 정확하다. 로고가 없는 학교는 목록으로 관리하고, 해결하지 못한 자산 문제가 남아 있으면 M1 전체를 완료로 처리하지 않는다.
