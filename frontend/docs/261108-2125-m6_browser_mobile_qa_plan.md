### 5-1. CDP 재연결과 검사 자체 결함의 원인

- 이전 `baseline` 실행은 Vite 시작 후 `Failed to find Chromium page target webSocketDebuggerUrl`로 실패했다. 이전 stderr가 없어 원인은 **미확인**이다. 사용자 요청 후 jail이 꺼진 환경에서 CDP 재연결·페이지 탐색·조작에 성공했지만, 이전 원인을 jail로 확정하지 않는다.
- **Enter 오검출:** 최소 재현에서 기존 `rawKeyDown`/`keyUp`은 버튼에 keydown/keyup을 전달했지만 click이 생성되지 않았다. `Page.bringToFront`만으로는 해소되지 않았다. 문자 단계가 포함된 `keyDown`(CR 문자 포함)/`keyUp`으로 바꾸자 앱 수정 없이 click·모달 열림 성공. `tests/e2e/cdp-input.mjs`로 분리하고 `tests/cdpInput.test.ts`에서 먼저 1개 실패→수정 후 3개 통과를 확인했다. [공식 Input 프로토콜](https://chromedevtools.github.io/devtools-protocol/tot/Input/#method-dispatchKeyEvent) 원문 PDL도 확인했다.
- **Tab 오검출:** Chromium은 모달 내부 순회를 마친 뒤 일시적으로 브라우저 UI로 포커스를 넘길 수 있다([HTML Standard §Sequential focus navigation](https://html.spec.whatwg.org/multipage/interaction.html#sequential-focus-navigation)). DOM의 `body` 센티널만 허용하고 **다음 동일 방향 Tab에서 즉시 모달 복귀**를 요구한다. 배경 컨트롤로 이동하면 실패하며, 열린 동안 원래 트리거의 `.focus()`도 차단되는지 별도로 검사한다. 모달의 애플리케이션 배경 차단 기준을 낮춘 것이 아니다.
- **이미지 오류 대체 오검출:** 전역 `querySelector('input')`이 URL 칸이 아닌 `[시연] 서버 클릭 거절 응답` 체크박스를 골랐다. 수정 전 로그는 샘플 입력값 `on`, 잘못된 URL 확인 버튼 `disabled: true`. 확인창 내부 URL 입력으로 범위를 좁히고 URL 값·버튼 활성화·적용 성공을 선행 단언한 뒤 대체 배지를 검증한다. 수정 후 기존 전체 검사 통과. 오류를 숨기거나 단언을 제거하지 않았다.
- 위 1차 CDP 재시도는 검사 수정/확장으로 당시 `src/`를 추가 변경하지 않았다. 이후 실기기 보고 대응에서는 앱 스크롤 잠금·새 글 좋아요 초기값을 변경했다(§6-5).
- 진단 재현·실패 로그: `key-repro/result.json`, `image-before.log`, `m6-extended-1/results/failure.json`(마지막 것은 확장 검사에서 전역 h1을 앱 제목으로 잘못 고른 문제이며 방문 캠퍼스의 레이블로 범위를 수정했다). 최종 통과 증거와 구분한다.
- `gh auth status` 및 `gh issue view 15` 재확인 성공. GitHub CLI 인증은 더 이상 차단 사유가 아니다. Issue 원문 M6 기준 3개를 다시 대조했다.

### 6-5. 실기기 보고 대응: 배경 스크롤과 새 글 좋아요

- **사용자 보고:** 우리 학교는 세로에서 목록 대신 뒤 페이지가 스크롤됨. 가로 전환 후 목록 스크롤이 가능해지기도 함. 회전/닫기/지도 이동 정상. 방문 학교는 입력/초안 정상, 학교 유지/버튼 접근/전송/복귀 대체로 정상이나 새 글에 자동 좋아요가 부여됨.
- **원인 확인:** `showModal()`의 배경 inert 처리를 페이지 스크롤 잠금으로 간주했던 누락이다. 수정 전 Chromium에서 목록의 상하 경계·backdrop 드래그 후 뒤 페이지가 135~160px 이동하고 닫기 후 위치도 달라졌다. 새 글은 `likeCount: 1`, `likedByMe: true`로 생성됐다.
- **위험도 추론:** 둘 다 런타임 조작 오동작으로 중위험(§3 #8·9), 현재 단계에서 수정하고 실기기 재확인을 열린 인수 과제로 둔다. 새 글 초기값 0은 에이전트의 수정 판단이며 기획서의 명시 수치로 기록하지 않는다. 직접 좋아요를 누르는 동작은 유지한다.
