# M5 실패·빈 목록·클릭 거절·재시도와 시연 모드 정리 계획

Last updated: 2026-11-08 21:12 +0900

## 1. 결론

M5는 기능 세 가지를 만들고 화면 한 가지를 정리한다.

1. **클릭 검증 모델:** 1초 단위로 클릭 횟수와 간격을 판정하는 순수 함수를 둔다. 거절된 클릭은 점수에 반영하지 않고 잠시 차단한 뒤 정상으로 돌아온다.
2. **목업 요청 계층:** 필수 흐름의 요청(인증, 구매·강화, 순위·지도·방문 조회)에 "정상 / 지연 / 1회 실패 / 계속 실패"를 고정 조작으로 적용한다.
3. **실패 처리:** 요청이 성공했을 때만 상태를 바꾸고, 대기 중에는 같은 요청을 막는다. 실패하면 입력을 남겨 둔 채 다시 시도할 수 있게 한다.
4. **시연 모드 구분:** 데모 메뉴를 "서비스 흐름"과 "시안 비교·시연 도구"로 나눈다.

무작위 실패는 쓰지 않는다. 실제 서버의 신원 검증, 어뷰징 탐지, 멱등성은 구현하지 않는다.

- **범위:** [Issue #15](https://github.com/Lemnoideae/261106-mkup/issues/15) 4장의 M5 작업 제안과 완료 기준 4개.
- **선행 묶음:** M1·M2·M4가 병합됐다(PR #26, #27, #28).
- **결정:** 6장의 D1~D5를 기본안으로 적용했다(사용자 지시 2026-11-08). 사용자가 키보드 클릭 규칙을 추가했다(M5-A, 9-2).
- **상태:** 구현과 자동·브라우저 검증을 마쳤다. PR #29로 병합한다. 결과는 9장.

## 4. 작업 계획

### M5-A. 클릭 검증 모델 (기획서 4-1 #5, 10장 #4)

- [x] `src/utils/clickGuard.ts`(신규)에 순수 함수를 둔다. `judgeTap(guardState, now, rules)`는 `{ accepted, reason: 'rate' | 'interval' | 'blocked' | 'forced', next }`를 반환한다. 시간은 인자로 받는다.
- [x] 판정 규칙(D2 기본안):
  - 최근 1초 창 안의 클릭 수가 한도를 넘으면 `rate`
  - 직전 클릭과의 간격이 최소 간격보다 짧으면 `interval`
  - 거절되면 차단 시간 동안 모든 클릭이 `blocked`이고, 차단이 끝나면 자동으로 풀린다
- [x] 거절된 클릭은 `tap` 동작으로 넘기지 않는다. 개인·학교·학과 점수, 1회용 버프, 피버 게이지가 모두 바뀌지 않는다.
- [x] 화면에는 거절 안내(`role="status"`, 예: "비정상적인 클릭으로 판단돼 반영하지 않았습니다. N초 후 다시 클릭할 수 있습니다.")와 "+0" 대신 "거절" 표시를 띄운다. 차단이 풀리면 안내가 사라진다.
- [x] 시연 토글 "[시연] 서버 클릭 거절 응답"을 둔다. 켜면 다음 클릭을 `forced`로 거절해서, 사람이 빨리 누르지 않아도 거절 경로를 재현할 수 있다.
- [x] 검증 상태는 게임 Provider 안에 둔다. 방문 화면의 관전 클릭은 지금처럼 점수와 상관없으므로 검증하지 않는다.
- [x] 화면 문구와 문서에 "목업 판정이며 서버 어뷰징 방지가 아님"을 적는다.

### M5-B. 목업 요청 계층과 실패·지연·재시도

- [x] `src/utils/mockRequest.ts`(신규)를 만든다. 요청 모드는 `normal | delay | fail-once | fail`이다.
  - `run(key, action)`은 대기 상태를 표시한다.
  - 지연 모드에서는 정해진 시간 뒤에 `action`을 실행한다.
  - 실패 모드에서는 `action`을 **실행하지 않고** 실패를 반환한다.
  - 같은 `key`가 대기 중이면 새 요청을 거절한다.
- [x] `useMockRequest()` 훅이 시연 모드와 대기 상태를 Provider에 둔다. 시간은 가짜 시계로 테스트할 수 있게 `setTimeout`을 주입받는다.
- [x] 적용 대상(D3 기본안). 상태를 바꾸는 요청은 성공했을 때만 반영된다.

  | 대상 | 요청 | 실패할 때 보존할 것 | 중복 방지 |
  |---|---|---|---|
  | 인증 | 코드 요청, 코드 확인, 프로필 완료 | 이메일 입력, 입력한 6자리, 닉네임·학과 선택 | 대기 중 버튼 비활성 + 같은 key 거절. 실패한 요청은 시도 횟수를 늘리지 않는다 |
  | 상점 | 커피 구매, 클리커 강화 | 선택한 아이템, 확인 창 | 대기 중 다시 누르면 무시. 재시도에 성공하면 잔액이 한 번만 줄어든다 |
  | 순위 | 순위 화면 조회 | 선택한 탭 | 로딩 표시, 실패 안내, "다시 시도" |
  | 지도·방문 | 학교 목록 조회, 방문 학교 조회 | 검색어·권역 필터, 고른 학교 | 로딩 표시, 실패 안내, "다시 시도", 지도 복귀 |

- [x] 실패 안내는 `role="alert"`로 표시하고 "다시 시도" 버튼을 함께 둔다. "1회 실패" 모드에서는 다시 시도하면 정상으로 성공해서 정상 화면으로 돌아온다.
- [x] 클릭 제출은 이 계층에 넣지 않는다. 클릭 거절은 M5-A에서 다룬다(D1).

### M5-C. 빈 목록

- [x] 지도 검색 0건과 없는 학교 방문은 이미 있으므로 회귀 테스트만 유지한다.
- [x] 필수 흐름에서 새로 생기는 빈 상태는 "조회 결과가 비어 있음" 하나다. 순위·지도 조회의 시연 모드에 `empty`를 추가할지는 D3에서 정한다. 기본안은 추가하지 않고 검색 0건으로 대신한다.

### M5-D. 시연 모드 구분

- [x] 데모 메뉴를 두 묶음으로 나눈다. 버튼과 화면은 삭제하지 않고 위치와 제목만 바꾼다.
  - **서비스 흐름:** 게임 플레이, 순차 온보딩, 지도, 순위, 상점, 연합·대결
  - **시안 비교·시연 도구:** 1·2·3-Phone 비교 화면, 지도 일러스트, 스프라이트 시트, 3단 온보딩
- [x] 시연 조작을 "[시연] 도구" 패널 하나에 모은다: 시간대, 학교명, 요청 모드(M5-B), 서버 클릭 거절(M5-A).
- [x] "[시연]" 표시가 없는 서비스 화면에서는 학교 점수를 직접 바꾸는 조작에 닿지 않게 한다.

- [x] 기존 게임 규칙 테스트(`tests/gameModel.test.ts`, `tests/gameUi.test.ts`)는 그대로 통과해야 한다.

A를 권고한다. 방식 B는 API 계약을 확정할 때 백엔드와 맞춰 볼 가치가 있으므로 이연 후보로 남긴다.
