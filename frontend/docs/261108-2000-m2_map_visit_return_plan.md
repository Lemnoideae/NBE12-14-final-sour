# M2 지도 → 방문 → 내 학교 복귀 계획

Last updated: 2026-11-08 20:14 +0900

## 1. 결론

지도에서 고른 학교 ID를 App이 보관하고, 방문 화면이 그 ID로 M1의 공통 조회(`getSchoolViews`)를 읽게 한다. 지도 문맥(권역·검색어·선택 학교)은 App으로 올려 방문 뒤 복원한다. 작업 순서는 M2-A(이동·방문 정보) → M2-B(관전 무득점·상태 보존 테스트) → 통합 검증이다.

- **범위:** [Issue #16](https://github.com/Lemnoideae/261106-mkup/issues/16) 4장의 M2-A(연결 전제 1~5)와 M2-B(항목 16~20). 선택 기능인 방명록은 D3에 따라 열기·닫기 연결만 다룬다.
- **필수 기능과의 관계:** 기획서 4-1 #6 "타 학교 방문: 타 학교의 학교 키우기 상황 조회"(필수)를 직접 다룬다. M1의 미충족 항목(로고 0/76, 4-1 #7)은 M2의 선행 조건이 아니다.
- **이미 맞는 부분(확인):** 방문 캠퍼스 클릭은 이미 득점하지 않는다(`src/components/VisitingScreen1Phone.tsx:32`–`:36`, 안내만 표시). 게임 Provider는 `App` 바깥에 있어 화면 전환으로 다시 만들어지지 않는다(`src/main.tsx:6`). 버프 만료 타이머는 Provider 안에서 화면과 관계없이 돈다(`src/hooks/useMockGame.tsx:71`). M2-B는 이 동작을 **테스트로 고정**하는 일이 중심이다.
- **결정:** 6장의 D1~D4는 사용자 지시("좋아, 기본안 그대로 진행해줘.", 2026-11-08)로 기본안을 적용했다.
- **구현 상태:** M2-A·M2-B 구현과 자동 테스트 완료. 결과는 9장.

## 4. 작업 계획

### 4-1. M2-A 이동과 방문 정보 (연결 전제 1~5)

**목표:** 지도에서 고른 학교의 방문 화면이 열리고, 그 학교의 이름·로고·점수·순위·캠퍼스 단계가 지도·순위와 같다. 돌아오면 지도 문맥이 그대로다.

- [x] **A1. 선택 상태 연결:** App에 `visitSchoolId`와 `mapContext`(권역·검색어·선택 학교 ID)를 둔다. 학교 데이터는 복사하지 않고 방문 화면이 `useSchoolViews()` + `getSchoolById`로 읽는다.
- [x] **A2. 지도 상태 올리기:** `MapScreenPhone`이 문맥을 props(`context`, `onContextChange`)로 받게 바꾼다. 내부 상태는 기본값이 필요한 비교 시안용으로만 남긴다.
- [x] **A3. 이동 규칙:** 아래 표대로 연결한다.

| 사용자 조작 | 동작 |
|---|---|
| 지도에서 타 학교 선택 (마커·목록 "방문"·TOP 3) | `visitSchoolId` 설정 → 방문 화면 |
| 지도에서 내 학교(`MY_SCHOOL_ID`) 선택 | 내 캠퍼스(`gameplay`, `activeTab='campus'`) |
| 방문 화면 "지도로 돌아가기"·하단 내비 지도 | 단일 지도, 이전 `mapContext` 복원 |
| 방문 화면 "내 학교로 돌아가기"·하단 내비 캠퍼스 | 내 캠퍼스, 게임 상태 그대로 |
| 방문 화면 방명록 열기·닫기 (D3) | 같은 학교 방문 화면으로 복귀 |

- [x] **A4. 방문 정보 교체:** `VisitingScreen1Phone`·`VisitingScreen2Phone`이 `schoolId`를 받는다. 이름·로고(`SharedImage` + 첫 글자 배지)·전국 순위·점수·캠퍼스 단계(`campusLevel`)·이미지 대체 텍스트를 `SchoolView`에서 읽는다. 기여 랭커 등 부가 정보는 D2에 따른다.
- [x] **A5. 잘못된 ID:** 공통 목록에 없는 ID면 다른 학교로 바꾸지 않고 "학교를 찾을 수 없습니다" 안내와 지도 복귀 버튼을 보인다.
- [x] **A6. 실제 이용 경로:** 게임 화면 지도 탭의 "전국 지도"와 방문 화면의 지도 이동을 **단일 지도**(`single_map`)로 연결한다. 2-Phone 지도·방문 비교 화면은 데모 진입점으로 유지한다(D1).
- [x] **A7. 고정 가상 학교 정리:** D4에 따라 방문 화면에서 `MOCK_VISITING_SCHOOL`을 걷어낸다. 공유 이미지·연합의 `blue-sea`는 이번 범위에서 바꾸지 않는다.

**완료 기준:** 서로 다른 두 학교를 연속 방문하면 화면의 학교 정보가 정확히 바뀌고, 그 값이 지도 목록·순위 화면의 같은 ID 값과 같다. 지도 복귀 시 권역·검색어·선택 표시가 방문 전과 같다. 잘못된 ID는 안내로 끝난다.

### 4-2. M2-B 관전 입력과 게임 상태 보존 (항목 16~20)

동작은 대부분 이미 맞으므로(3-3절) 회귀 테스트를 먼저 쓰고, 실패하는 항목만 고친다.

- [x] **16. 관전 입력:** 방문 캠퍼스 클릭 시 안내만 나오고 `game.tap`이 호출되지 않는다. 내 캠퍼스의 득점 연출(점수 팝업·파티클)이 방문 화면에 나오지 않는다.
- [x] **17. 상태 변경 금지:** 방문 클릭 전후로 `state`(학교·학과 점수, 기여도, 클리커, `activeBuff`의 종류·만료 시각)가 같다. 시간을 고정해 검사한다.
- [x] **18. Provider 유지:** 내 캠퍼스 → 지도 → 방문 → 내 캠퍼스 왕복 뒤 기여도·클리커·유효한 버프가 그대로이고, 복귀 직후 클릭이 정상 득점한다.
- [x] **19. 버프 시간:** 방문 중에도 만료가 처리된다. 1회 버프는 방문 클릭으로 소비되지 않고 복귀 후 첫 클릭에서 소비된다. 이동이 버프를 교체·연장하지 않는다.
- [x] **20. 비교 화면:** 2-Phone 방문 비교 화면의 관전 폰 클릭이 점수·피버 게이지를 바꾸지 않는다. 새 연결로 중복 득점 경로가 생기지 않았는지 `handleCampusTap` 호출처를 확인한다.

**완료 기준:** 관전 클릭은 무득점이고, 지도 문맥과 내 학교 게임 상태가 유지되며, 복귀 후 정상 클릭이 된다(Issue #16 4장 M2 완료 기준).

## 5. 권장 순서와 대안

1. M2-B 회귀 테스트를 **먼저** 쓴다(지금 통과해야 함). 이후 M2-A 작업 중 득점 경로가 새로 생기면 바로 잡힌다.
2. A2(지도 상태 올리기) → A1·A3(App 이동) → A4·A5(방문 정보) → A6(실제 경로) → A7(정리).
3. 통합 테스트와 Chromium 확인.

**대안:** 방문 화면을 지도 화면 안의 오버레이로 띄우면 지도 상태를 올리지 않아도 된다. 하지만 하단 내비·복귀 경로가 화면마다 달라지고, 내 학교 복귀가 App의 `viewMode`와 따로 놀게 된다. 이동을 App 한 곳에서 다루는 기본안을 권한다(에이전트 판단).

| 방문·복귀 | A 방문 → 지도 복귀 → B 방문에서 학교명·순위·점수·캠퍼스 단계가 각 `SchoolView`와 같음; 내 학교 선택 시 내 캠퍼스; 잘못된 ID 안내 |
| 지도 문맥 | 권역(예: 영남)·검색어·선택 학교를 정한 뒤 방문 → 복귀하면 칩 `aria-pressed`·검색 입력값·선택 표시가 같음 |
| 데이터 일치 | 방문 화면의 순위·점수 = 순위 화면의 같은 ID 값; 내 점수를 바꿔 순위가 바뀌면 방문 화면도 바뀜 |
| 관전·버프 | 시간 고정 상태에서 방문 클릭 N회 → `state` 동일, 1회 버프 미소비; 시간을 진행시키면 방문 중에도 만료 |
| 게임 보존 | 왕복 후 기여도·클리커·버프 만료 시각 동일, 복귀 후 첫 클릭 득점 |
| 비교 화면 | 2-Phone 방문 비교 화면 클릭이 점수·피버 게이지를 바꾸지 않음 |
