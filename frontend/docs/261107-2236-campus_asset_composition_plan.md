# 캠퍼스 에셋화·장면 조합 계획

Last updated: 2026-11-08 10:33 +0900

## 1. 결론

Lv.1~10을 5×2로 담은 캠퍼스 성장 시트 한 장을 개별 투명 PNG 에셋으로 나눈다. 레벨별 장면은 **배치 데이터와 간단한 렌더러**로 조합한다.

- **화풍:** 현재 시트의 화풍을 따른다. 시계탑 본관을 기준 에셋으로 먼저 확정한 뒤, 이후 모든 생성에 참고 이미지로 넣는다.
- **조합:** 레벨마다 고정 배치 목록을 두고, 렌더러가 바닥 좌표 y 순서로 정렬해 겹쳐 그린다. 사용자가 직접 배치하거나 저장하는 기능은 범위 밖이다.
- **지형:** 잔디·흙·보도·물은 반복 텍스처만 이미지로 만든다. 길과 연못의 모양·경계는 SVG로 그린다.
- **생성:** Herdr에서 실행 중인 Pi 에이전트가 자작 확장 `vertex-image`의 `generate_image` 도구(Nano Banana 2.1)로 생성한다. 이 Claude 세션은 **영어 프롬프트**가 담긴 요청 파일을 작성하고 결과를 검토한다.
- **투명 배경:** 본 작업 전에 Pi에게 투명 배경으로 시험 생성을 시킨다. 결과에 알파 채널이 있으면 그대로 쓰고, 없으면 단색 배경(마젠타 또는 시안)으로 생성한 뒤 로컬에서 제거한다.
- **방문 화면:** 방문 화면 3곳도 조합 장면으로 바꾸고, 방문한 학교의 레벨로 표시한다.

이 작업은 **기획서 4-1 필수 기능이 아니다.** 사용자 지시로 추가하는 선택 범위이며, 4-1 필수 기능 완료의 선행 조건으로 두지 않는다. 단계마다 기존 시트를 대체 경로로 남겨 두므로, 중간에 보류해도 현재 화면은 유지된다.

### 5-1. 화풍 고정 값

| 항목 | 값 |
|---|---|
| 시점 | 2:1 아이소메트릭. 바닥 1칸은 64×32px 마름모 |

| 팔레트 | **64색.** `scripts/assets/build_palette.py`가 원본 이미지마다 같은 수의 표본을 뽑아 만든 공용 팔레트를 `art/palette.png`(64×1)로 고정한다. A1-b의 48색 팔레트는 벚꽃 분홍이 표본에서 밀려 꽃이 바래 보였고, 64색은 48색보다 벽돌 색이 원본에 가까웠다(13절). 새 원본을 추가하면 팔레트를 다시 만들고 모든 에셋을 다시 처리한다 |

| 에셋 크기 기준 | 축소 배율을 고정하지 않고 **에셋별 목표 폭**으로 정한다. 기준: `main-clocktower` 폭 134px(원본 테두리 상자 폭 ÷ 12). 다른 에셋은 실제 크기 비율로 목표 폭을 정해 `campusAssets.ts`에 기록한다 |

### 5-2. 생성 해상도 (1K와 2K)

최종 에셋은 1배 픽셀 크기(건물 약 64~200px, 소품 약 16~64px)로 줄여 쓴다. 따라서 해상도를 높여도 최종 결과의 크기는 같고, 차이는 **축소 전 원본의 선명도와 픽셀 격자 추정의 정확도**에서 난다(추론).

| 기준 | 1K | 2K |
|---|---|---|
| 1장에 여러 개를 담는 시트 | 칸당 약 300px 안팎. 소품에는 충분할 것으로 예상 | 칸당 약 600px 안팎. 9칸 이상 시트에 유리 |
| 단독 건물 | 기준 에셋 수준의 세부 표현이 가능한지 시험 필요 | 창문·시계 같은 세부가 덜 뭉개질 것으로 예상 |
| 배경 제거·격자 맞춤 | 그림 픽셀 1개가 출력 픽셀 몇 개인지 추정 오차가 큼 | 오차가 작음 |
| 비용·시간 | 낮음 | 높을 가능성. 미확인 |

**확정: 모든 생성은 2K로 통일한다**(사용자 지시 2026-11-07, A1-a 결과 11절). 4K는 쓰지 않는다. 2K 시트에서 그림자가 생긴 문제는 프롬프트의 그림자 금지 문구를 강화해 대응한다(`art/prompts/style.md`).

### 5-3. 생성 프롬프트 공통 조건

- 프롬프트는 **영어로** 작성한다(사용자 지시 2).
- 위 화풍 값, 참고 이미지(기준 에셋 확정 후에는 `main-clocktower`), 배경 조건을 매번 명시한다. 공통 문구와 고정 매개변수는 `art/prompts/style.md`에 있다.
- 시트로 생성할 때는 칸 수, 칸 사이 여백, "칸 밖으로 넘치지 않음"을 명시한다.
- 그림자는 에셋에 포함하지 않는다. 바닥 그림자는 렌더러가 반투명 타원으로 그린다. 배경 제거 때 그림자가 깨지는 문제를 피하기 위해서다.
- **확정: 단색 배경으로 생성하고 로컬에서 제거한다**(사용자 지시 2026-11-07). A1-a에서 투명 요청이 알파 없는 흰 배경으로 나왔기 때문이다(11절).

| 시험 결과 | 배경 조건 |
|---|---|
| PNG에 알파 채널이 있고 배경이 실제로 투명함 | `transparent background`로 생성. 5-4의 1~2단계 생략 |
| 알파가 없거나, 투명 대신 체크무늬를 그려 넣음 | 아래 단색 배경으로 생성 |

| 대상 (단색 배경일 때) | 배경색 | 이유 |
|---|---|---|
| 기본 | 마젠타 `#FF00FF` | 잔디 초록과 겹치지 않음 |
| 벚꽃 나무, 꽃, 화단, 분홍 소품 | 시안 `#00FFFF` | 마젠타는 분홍 꽃잎과 비슷함 |
| 텍스처 | 배경 없음 | 화면 전체를 채우는 정사각 이미지 |

### 5-4. 후처리 파이프라인

`scripts/assets/`에 Python(PIL) 스크립트로 둔다. 원본은 Pi 확장이 저장하는 `generated-images/`(`tool.ts:163-164`)를 그대로 원본 보관 위치로 쓰고, 번들에는 넣지 않는다.

1. **배경 제거:** 이미지에서 가장 많이 쓰인 색을 배경색으로 잡고(마젠타 요청 결과의 초록 성분이 2~50으로 매번 다르기 때문), 그 색과의 RGB 거리가 70 이하인 픽셀을 투명으로 만든다. 거리 70은 A1-b 시험값이다.
2. **테두리 색 번짐 제거:** 투명 영역에 닿은 픽셀 중 배경색 쪽으로 치우친 픽셀을 제거하거나 보정한다. 투명 배경 생성이 되면 생략한다.
3. **시트 분할:** 투명 영역을 기준으로 연결된 덩어리를 찾아 자르고, 지정한 ID 순서대로 저장한다.
4. **축소와 색 줄이기:** 먼저 `art/palette.png`로 색을 줄인 뒤(디더링 없음), 목표 폭에 맞춘 블록마다 **가장 많은 색**을 고르는 방식으로 축소한다. 블록의 절반 넘게 투명하면 투명 픽셀로 둔다. A1-b에서 생성 이미지에 일정한 픽셀 격자가 없음을 확인했고(배율 4~16에서 오차가 단조 증가), 최근접 보간은 잡티가 많아 쓰지 않는다. 가는 물체(삽, 묘목)는 목표 폭 대신 **목표 높이**(`targetHeight`)로 정한다. 텍스처는 원본의 그림 픽셀(약 8px)에 맞춰 256×256으로 줄인다.
5. **기준점 기록:** 에셋의 바닥 중심점(앵커)을 계산해 `src/data/campusAssets.ts`에 기록한다.
6. **텍스처 이음매 검사:** 텍스처는 가장자리를 반대편과 비교해 이음매 차이를 보고한다.

후처리는 이 Claude 세션이 맡는다. Pi는 생성만 맡는다(6절).

### 5-6. 렌더러

- 레이어 순서: 하늘(CSS) → 해·달·별·구름 → 원경 → 지형(SVG) → 바닥 그림자 → 오브젝트·건물(앵커 y 오름차순, 같으면 x) → 밤 불빛 마스크 → 기존 `CampusAmbience` → 파티클.
  - **구현(A4~A5):** 하늘은 CSS가 아니라 SVG 그라데이션(Lv.4~10만)이고, 그 뒤에 효과(불꽃놀이·축제 빛)를 그린다. 밤 불빛 마스크·가로등 불빛은 `CampusScene` 안이 아니라 `CampusAmbience`의 틴트 위(`CampusSceneLights`)에 그려 어두워지지 않게 했다.
- 배치 항목 형식: `{ asset, x, y, flip?, layer? }`. 좌표는 장면 논리 크기 기준 픽셀이다.
- 지형 형식: `{ texture, points, edgeColor }`. SVG `pattern`으로 채우고 `shape-rendering: crispEdges`, 정수 좌표를 쓴다.
- `CampusSprite`와 같은 속성(`level`, `className`, `variant`)을 받는다. 해당 레벨의 배치 데이터가 없으면 `CampusSprite`로 대체한다. A4 이후 Lv.1~10 모두 배치가 있으므로 대체는 범위 밖 레벨에만 쓰인다.
