## 1. 결론

- 피드백을 **공통 단계 1개(U0)와 레벨별 단계 7개(U4~U10)**로 나눈다. 단계마다 수정, 배치 검증, 전후 촬영, 사용자 확인, 커밋을 거친 뒤 다음 단계로 넘어간다.
- 공통 단계를 먼저 하는 이유: "길을 하나로 잇기"와 "소품을 길 밖으로"는 Lv.4~10 모두에 해당한다. 이 두 규칙을 배치 검증(`validateCampusLayouts`)에 먼저 넣어 두면, 레벨별 단계에서 기준을 다시 정하지 않아도 된다. 또한 현재 배치에서 실제로 위반을 찾아내므로 수정 대상 목록으로 쓸 수 있다.
- 구현 전에 사용자 결정이 필요한 항목이 6개 있다(3절). 특히 Lv.5에서 "앞 건물 제거"는 단계 특징 "중앙도서관"과 충돌할 수 있고, Lv.8·9의 "다시 생성"은 배치를 다시 짜는 것인지, 에셋을 새로 생성하는 것인지에 따라 작업량이 크게 달라진다.

## 5. 단계 계획

모든 단계에 같은 절차를 쓴다.

1. 수정 전 해당 레벨을 낮·밤으로 촬영한다(`quick.mjs`, 작업 폴더).
2. 배치를 수정한다(`src/data/campusLayouts.ts` 중심).
3. `npm run lint`, `npm test`, `npm run build`를 실행한다. 배치 검증 규칙을 통과해야 한다.
4. 수정 후 촬영본과 성장 시트를 나란히 놓고, 해당 피드백 항목을 하나씩 대조한다.
5. 사용자(필요하면 팀장) 확인을 받은 뒤 커밋한다. 다음 단계로 넘어간다.
