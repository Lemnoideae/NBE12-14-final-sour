## 4. T1 — 공통 폰 셸(2-2)

**목표 [지시]:** 모든 게임 화면과 비교 목업의 크기·비율을 하나의 기준으로 통일한다. 그 구조가 나중에 실제 프런트엔드 레이아웃으로 이어지게 한다.

**설계 [권고]:**

- 기준 크기: **390×844 논리 px**(19.5:9). 지금의 390×845와 1px 차이다. 16:9는 같은 셸의 360×640 변형으로 확인한다(§5).
- 새 컴포넌트 `src/components/PhoneShell.tsx`:

```text
<PhoneShell variant="framed|full" testId>
  <StatusBar/>            // framed일 때만. 목업 상태바 마크업을 하나로 모음
  header 슬롯             // shrink-0
  main 슬롯               // flex-1 min-h-0 overflow-y-auto overscroll-contain
  footer 슬롯             // shrink-0. ChatPreviewBar, BottomNav
  overlay 슬롯            // 시트·모달 포털 기준
</PhoneShell>
```

- `framed`는 데스크톱 발표용이다. 고정 390×844에 테두리와 그림자를 둔다.
- `full`은 실제 모바일용이다(§5). 슬롯 구조는 두 변형이 같다. 그래서 나중에 실제 서비스로 옮길 때 `full` 경로만 가져가면 된다. 계획은 `docs/261108-1122-main_screen_layout_plan.md` M1·M7과 맞춘다.
- 적용 대상은 §2-1의 화면 전부(목업 약 20개)다.
  - 지도 화면과 상점은 400×866에서 390×844로 바뀐다. 지도는 `MAP_DESIGN_FRAME_PX`와 `mapLayerFit`가 영역을 덮는 비율로 축소하므로, 마커 잘림 검사(`MAP_AREAS_PX`)에 새 영역 크기를 넣는다.
  - 온보딩 `PhoneFrame`(340/350×758)도 390×844 셸로 통일한다 [결정 Q4]. 크기만 맞추고 온보딩 연출(타이틀 장면, 단계 전환)은 바꾸지 않는다. 타이틀 장면은 정사각형 배치이므로, 새 폭에서 로고·배지 띠 위치를 다시 측정한다(`docs/261110-0837-onboarding_title_screen_plan.md`).
  - `MapIllustrationViewer`는 이미지 뷰어라 대상에서 뺀다.
- 2-Phone 비교 화면은 셸 두 개를 나란히 놓는다. 크기는 같다.

**완료 기준:**

1. 프레임 크기 클래스(`h-[845px]`, `h-[866px]`, `max-w-[400px]` 등)가 `PhoneShell` 밖에 없다. 테스트로 소스를 검색해 확인한다.
2. 목업 메뉴의 모든 화면과 온보딩 각 단계에서 셸 루트 크기가 같다. JSDOM에서는 클래스로, Playwright에서는 `getBoundingClientRect`로 확인한다.

  ```text
  ┌──────────────┐
  │ 📊 상세 스탯 │   ← 픽셀 막대그래프 아이콘(SVG) + 글자
  │   12,345 P   │   ← 보유 기여도
  └──────────────┘
  ```

  - **큰 수 줄여 쓰기 [지시 2026-11-10]:** 영어 단위 이니셜을 쓴다. M은 Million, B는 Billion, T는 Trillion이다.

    | 보유 기여도 | 표시 |
    |---|---|
    | 0 ~ 999,999 | `999,999` (그대로, 천 단위 쉼표) |
    | 1,000,000 이상 | `1.2M` |
    | 1,000,000,000 이상 | `3.4B` |
    | 1,000,000,000,000 이상 | `5.6T` (그 이상도 T로 표시. 예: `1234.5T`) |

### 10-2. T8 지도 확대와 포커스 이동(3-2)

**목표 [지시]:**

- 기본은 축소된 전국 지도다. 지역 버튼을 누르면 확대된다(3-2-1).
- 새 지역의 대학은 fade in으로 나타나고, 이전 대학은 fade out 없이 즉시 사라진다(3-2-2).
- 다른 지역으로 바꾸면 포커스가 부드럽게 이동한다(3-2-3).

**설계 [권고]:**

- **지도 하나, 카메라 하나:** `Screen2RegionMap`(충청 전용)과 `Screen1NationalMap`을 지도 컴포넌트 하나로 합친다.
  - 충청도 `regionViewport('충청')`를 쓴다.
  - 충청의 고정 배율 2.3과 `regionViewport` 결과가 다르면 구도가 바뀐다. 마커 겹침 테스트로 확인한다.
  - `MapScreenPhone.tsx:60`의 분기를 없앤다.
- **월드 레이어:** 바다, 육지, 섬, 구름, 마커를 모두 같은 `world` 컨테이너에 넣는다.
  - 카메라 변환은 `transform: translate(px) scale(z)`이고 `transform-origin: 0 0`이다. 선형 이동이 되도록 이 순서를 고정한다.
  - 마커는 지도 % 좌표에 놓고 `scale(1/z)`로 크기를 유지한다. 그래야 마커가 지도와 함께 움직인다.
  - 지금의 `projectToViewport` 계산은 테스트용으로만 남긴다.
- **전환:** 카메라는 `transition: transform 500ms ease-in-out`이다.
  - 지역에서 지역으로 갈 때는 직접 보간한다. 전국을 거쳐 돌아가지 않는다.
  - 전환 도중에 다른 지역을 누르면 현재 위치에서 새 목표로 이어서 간다. CSS 전환이 이를 기본으로 처리한다(추론).
- **마커 표시:**
  - 지역이 바뀌면 이전 마커 목록을 즉시 언마운트한다. 마커 컨테이너의 `key`를 지역으로 둔다.
  - 새 목록은 `opacity 0→1` 250ms로 나타난다. 시작 시점은 카메라 이동 40%쯤이다(선택. 기본은 바로 시작).
  - 전국으로 돌아갈 때 군집 말풍선과 TOP3에도 같은 규칙을 쓴다.
- **reduced motion:** 카메라와 페이드 시간을 0으로 둔다.

**완료 기준:**

1. 첫 렌더는 전국 카메라 `{cx 50, cy 50, zoom 1}`다.
2. 충청을 포함한 7개 권역 버튼 모두에서 같은 컴포넌트가 유지된다. `data-map-world` 노드가 다시 마운트되지 않는다(테스트).
3. 지역을 바꾸면 이전 지역 마커 노드가 다음 렌더에 즉시 없고, 새 마커에 페이드 클래스가 있다.
4. 전환 도중 Playwright로 캡처했을 때 마커와 지도 사이 상대 위치가 고정돼 있다. 같은 학교 마커와 그 아래 지도 픽셀의 거리를 프레임별로 비교한다.
5. 기존 지도 테스트와 새 셸 크기의 잘림 검사가 통과한다.
