## 2. 현재 문제 (에이전트 판단)

- 시트는 2026-11-06에 생성한 그림이라 지금의 인게임 장면과 다르다. 예를 들어 Lv.10은 지금 ㄱ자 일체형 건물이고, Lv.1~3에는 새 소품이 있다. 그래서 시연할 때 시트와 인게임 화면이 서로 맞지 않는다.
- 시트는 윗줄 304px, 아랫줄 464px로 칸 높이가 고르지 않아 클릭 영역도 `304fr 464fr`로 맞춰 두었다(`SpriteSheetViewer.tsx:81`).

## 3. 방식 비교

| 기준 | A. 미리 찍은 스크린샷 10장 (사용자 제안) | B. 화면에서 `CampusScene` 10개를 바로 그림 |
|---|---|---|
| 인게임과 일치 | 레이아웃을 바꾸면 다시 찍어야 한다. 이 차이는 5-3절의 검사로 잡는다 | 항상 일치 |
| 화면 부하 | 이미지 10장 | 장면 10개. 장면마다 스프라이트 수십~수백 개(Lv.10 학생 48명 등)와 HD 파일을 내려받는다 |
| 번들 크기 | WebP q90 기준 장당 약 127KiB(Lv.3 시험 변환), 10장 약 1.3MiB(추정). 기존 시트 JPG는 882KiB | 추가 파일 없음 |
| 구현량 | 촬영 스크립트, 이미지 등록, 오래된 이미지 검사 | 화면 구성만 바꾸면 됨 |

**권고: A.** 이 화면은 10단계를 한눈에 비교하는 시연용이라 휴대폰에서 장면 10개를 동시에 그리는 B는 부담이 크다. A의 약점(촬영 후 레이아웃이 바뀌면 이미지가 낡음)은 5-3절의 테스트로 막는다(에이전트 권고).

## 5. 구현

### 5-1. 촬영 모드와 스크립트

- `src/main.tsx`에 개발 서버 전용 촬영 모드를 둔다. `?campusShot=<level>`이면 앱 대신 `CampusScene` 하나만 고정 폭·낮 시간대로 그린다. `import.meta.env.DEV`가 아니면 무시한다(목업 도구, 서비스 기능 아님).
- `scripts/campus-shots/capture.mjs`(Playwright): 실행 중인 개발 서버의 촬영 모드를 열고, 스프라이트가 모두 로드되기를 기다린 뒤 10장을 찍어 WebP로 저장한다. 입력 해시도 함께 쓴다. `package.json`에 `"campus:shots"` 스크립트를 추가한다.
- 대안: 지금처럼 메뉴를 눌러 들어가 찍는 방식(`quick.mjs`)은 앱 코드를 바꾸지 않지만, UI가 함께 찍히고 메뉴 문구가 바뀌면 깨진다.

### 5-2. 화면

- `SpriteSheetViewer`: 시트 한 장 대신 레벨 이미지 10장을 5×2 격자(좁은 화면은 2열)로 놓는다. 각 칸이 선택 버튼이고, 칸 높이를 같게 맞춘다. 아래의 단계 선택 막대, 상세 패널, 시연 버튼은 그대로 둔다.
- 화면 제목 "…성장 스프라이트 시트 (5x2 Grid)"와 부제를 실제 화면 기준으로 바꾼다. 메뉴 버튼 이름("🏛️ 10단계 캠퍼스 성장 시트 (5x2)", "[시연] 성장 시트 보기")은 그대로 둔다. 테스트 4곳과 e2e가 이 이름을 쓰고, 5×2 격자도 유지되기 때문이다(7절 D3).
- `CampusSprite`(범위 밖 레벨의 대체 화면): 시트를 자르지 않고 해당 레벨 스크린샷을 그린다. 그러면 시트 JPG가 더 이상 번들에 포함되지 않는다. 원본 JPG는 Pi 요청의 참고 이미지로 계속 쓰므로 저장소에서 지우지 않는다.

### 5-3. 낡은 스크린샷 검사 (회귀 센서)

- `shots.json`에 레벨마다 입력 해시를 저장한다. 해시 입력은 해당 레벨 레이아웃 데이터(JSON), 그 레이아웃이 쓰는 에셋 파일(1x·HD) 바이트, 단계 정의(`CAMPUS_STAGES`)다.
- `tests/campusShots.test.ts`: 현재 입력으로 다시 계산한 해시가 `shots.json`과 다르면 실패하고 "`npm run campus:shots`로 다시 찍으라"는 안내를 출력한다. 10장 파일이 모두 있는지, 크기가 같은지도 확인한다.
- 한계: 그리기 코드(`CampusScene.tsx`)만 바뀐 경우는 해시에 들어가지 않아 잡지 못한다. 그리기 코드까지 해시에 넣으면 무관한 수정에도 매번 다시 찍어야 하므로 넣지 않는다(에이전트 판단, 7절 D4).

### 5-4. 테스트 변경

- `tests/campusScene.test.ts:328`: 대체 화면이 시트 대신 Lv.10 스크린샷을 그리는지 확인하도록 바꾼다.
- 성장 시트 화면: 이미지 10장이 각자의 레벨 이름을 대체 텍스트로 갖는지, 칸을 누르면 그 레벨이 선택되는지 확인한다.
- `tests/e2e/mobile-flows.mjs`의 성장 시연 흐름은 메뉴 이름을 유지하므로 그대로 통과해야 한다.
